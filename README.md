# BeCompare — x64 어셈블리 구현 (Win32 GUI)

파일·폴더 비교 도구 기능 PRD를 기반으로 **x64 NASM 어셈블리**로 구현한 Windows GUI 비교·병합·동기화 도구입니다.
C 런타임은 `printf`/`malloc`/`qsort` 같은 범용 함수에만 쓰고, 화면·스레드·파일·알고리즘은 모두 어셈블리입니다.

> PRD(공개 정보를 정리한 문서)의 요구사항을 따라 만든 독립 구현입니다.

## 빌드

### 준비물

| 도구 | 용도 | 확인 |
| --- | --- | --- |
| Windows 10 이상 (x64) | 실행·빌드 환경 | |
| NASM 2.16 이상 | 어셈블 (`nasm -f win64`) | `nasm -v` |
| MinGW-w64 (`gcc`, `windres`) | 링크·리소스 컴파일 (UCRT 빌드 권장) | `gcc --version` |
| PowerShell 5.1 이상 | 빌드 스크립트 실행 | |
| Python 3 (선택) | 정적 검사·회귀 검사 | `python --version` |

NASM과 MinGW-w64는 `PATH`에 있어야 합니다. 예: `winget install NASM.NASM`, `winget install BrechtSanders.WinLibs.POSIX.UCRT`.

### 빌드 순서

```powershell
git clone https://github.com/smseven/becompare.git BeCompare
cd BeCompare

powershell -File build-gui.ps1      # gui/*.asm -> build/*.obj -> bcgui.exe (GUI, 메인 프로그램)
powershell -File build.ps1          # src/bc.asm -> bc.exe (이전 단계의 콘솔 도구, 선택)
```

- 성공하면 마지막 줄에 `built bcgui.exe`(또는 `built bc.exe`)가 출력되고 실행 파일이 저장소 루트에 만들어집니다. 중간 산출물은 `build/`에 쌓입니다.
- `build-gui.ps1`은 `gui/`의 모듈을 하나씩 `nasm -f win64`로 어셈블하고, 리소스(`gui/res/app.rc`, 매니페스트)를 `windres`로 컴파일한 뒤 `gcc -mwindows`로 링크합니다. 링크 라이브러리: user32, gdi32, comctl32, comdlg32, shell32, ole32, dwmapi, wininet, gdiplus, uxtheme, shlwapi, version, advapi32.
- 새 모듈을 추가하면 `build-gui.ps1`의 `$optional` 목록에 이름을 넣어야 링크됩니다.

### 검사 (빌드 후)

```powershell
python tools/hazard.py              # invoke 인자 덮어쓰기 / 스택 프레임 16바이트 정렬 정적 검사 -> "hazards: 0" 이어야 함
python tools/test_regressions.py    # 격리된 경로에서 재빌드 + 저장 오류·상태·화면 동작·명령줄 회귀 검사 381개
powershell -File tools/manual/t_smoke.ps1  # 세션 유형 14가지가 3초 이상 살아 있는지 확인 (실제 창을 띄움, 수동 확인용)
```

### 자주 막히는 곳

- `nasm`/`gcc`/`windres`를 찾지 못함: 설치 후 새 터미널을 열어 `PATH`를 다시 읽게 합니다.
- `cannot open output file ..\bcgui.exe: Permission denied`: 실행 중인 `bcgui.exe`를 종료한 뒤 다시 빌드합니다.
- `symbol ... not defined` (NASM): 새 상수·문자열을 추가한 파일에서 `extern`/`%define`을 확인합니다.
- 화면 캡처형 시험 스크립트(`tools/manual/t_*.ps1`)는 실제 창을 띄우고 화면 좌표·임시 폴더를 가정하므로 자동 검사에 쓰지 않습니다. 참고용이며 [tools/manual/README.md](tools/manual/README.md)에 설명이 있습니다.

## 실행

```
bcgui.exe                                   홈 화면 (세션 유형 선택, 최근 세션)
bcgui.exe folder A B                        폴더 비교 (dir, .zip, .bcss 스냅샷, ftp:// 가능)
bcgui.exe text|diff A B                     텍스트 비교
bcgui.exe table|csv A B                     표 비교 (CSV/TSV/XLSX)
bcgui.exe hex A B                           헥스 비교
bcgui.exe picture|pic|image A B             이미지 비교
bcgui.exe merge LEFT RIGHT [BASE] [OUT]     텍스트 병합 (BASE 있으면 3-way)
bcgui.exe foldermerge LEFT RIGHT [BASE] [OUT]  폴더 병합 (3-way)
bcgui.exe version A B                       파일 버전 리소스 비교
bcgui.exe registry KEY_A KEY_B              레지스트리 키 비교 (예: HKCU\Software\X)
bcgui.exe media A B                         오디오 태그 비교 (MP3 / FLAC)
bcgui.exe edit FILE                         텍스트 편집
bcgui.exe file.bcs | file.bcw               세션 / 워크스페이스 열기
bcgui.exe /script file.bcscript             스크립트 실행 (화면 없음)
```

자동화 스위치 (명령줄 인터페이스, AU-04/05):

| 스위치 | 설명 |
| --- | --- |
| `/report out.html` | 폴더 비교 결과를 HTML 보고서로 저장하고 종료. 변경된 텍스트 파일은 `out_files\N.html` 상세 비교 보고서로 링크. 종료 코드 0=동일, 1=차이, 2=오류 |
| `/report out.xlsx` · `/report out.docx` | 확장자가 `.xlsx` / `.docx` 이면 같은 결과를 Excel 통합 문서 / Word 문서로 저장 (파일별 상세 보고서 링크는 HTML에만 있음) |
| `/xlsx out.xlsx` | 텍스트·표·헥스 비교 결과를 Excel로 저장하고 종료 (폴더 비교는 `/report out.xlsx`). 종료 코드 0=동일, 1=차이, 2=오류. 시트 한 장에 들어가는 1,048,575행까지만 기록 |
| `/docx out.docx` | 텍스트 병합·폴더 병합·이미지·버전·레지스트리·미디어 비교 결과를 Word로 저장하고 종료. 종료 코드는 이미지·버전·레지스트리·미디어가 0=동일, 1=차이, 텍스트 병합·폴더 병합이 0=충돌 없음, 1=충돌 남음, 공통으로 2=오류 |

화면 없는 실행(`/report`, `/sync`, `/snapshot`, `/xlsx`, `/docx`, `/exit`)의 공통 규칙:

- `/exit` 만 주면 모든 세션이 첫 비교를 마친 뒤 위와 같은 종료 코드로 끝납니다(예: `bcgui.exe text A B /exit` 는 0=동일, 1=차이). 실행할 비교가 없는 세션(입력이 하나뿐이거나 `edit`)은 열고 바로 닫습니다.
- `/xlsx`·`/docx` 는 입력 두 개가 모두 있어야 하고 위에 적힌 세션에서만 동작합니다. 세션 유형이 맞지 않거나, 입력이 빠졌거나, 세션 없이 스위치만 준 경우에는 종료 코드 2로 끝납니다.
- 확인만 누르는 알림창(파일을 읽을 수 없음 등)은 띄우지 않고 종료 코드 2로 끝냅니다. 입력을 읽지 못한 비교는 빈 결과 문서를 남기지 않습니다.
- 예/아니요를 묻는 창은 띄우지 않고 아무것도 쓰지 않는 쪽(아니요·취소)으로 답합니다. 닫을 때의 "저장하시겠습니까?" 는 저장하지 않고 닫습니다.
| `/sync update\|mirror\|twoway` | 비교 후 동기화(확인 창 없음). 미러는 오른쪽에만 있는 항목을 휴지통으로 보냄 |
| `/snapshot file.bcss` | 왼쪽 폴더의 스냅샷(상대 경로·크기·시각·CRC32)을 저장하고 종료 |
| `/exit` | 작업이 끝나면 종료 |
| `/save file.bcs`, `/savews file.bcw` | 열린 세션 / 워크스페이스를 저장 |
| `/shellinstall`, `/shelluninstall` | 탐색기 오른쪽 클릭 메뉴(현재 사용자) 등록 / 해제 |

스크립트 언어 (AU-04): 한 줄에 하나, `;` 또는 `#` 로 주석.

```
set L=%SCRIPTDIR%\left
set R=%SCRIPTDIR%\right
echo comparing %L% and %R%
run folder %L% %R% /report %SCRIPTDIR%\out.html     ; 작업 1개를 화면 없이 실행하고 ERRORLEVEL 설정
if errorlevel 1 goto diff
exit 0
:diff
exit 7
```

로그는 `<스크립트>.log` 에 남고, 종료 코드는 마지막 `exit` 또는 마지막 작업의 값입니다.

VCS 외부 도구 연동 (IN-01), 예: Git

```
git config --global diff.tool becompare
git config --global difftool.becompare.cmd 'bcgui.exe text "$LOCAL" "$REMOTE"'
git config --global merge.tool becompare
git config --global mergetool.becompare.cmd 'bcgui.exe merge "$LOCAL" "$REMOTE" "$BASE" "$MERGED"'
```

단축키(설정에서 변경 가능): `F5` 비교 · `Ctrl+S` 저장 · `Ctrl+W` 탭 닫기 · `Ctrl+Tab` 다음 탭 · `F8`/`Shift+F8` 다음/이전 차이(텍스트·헥스) · `Esc` 취소 · `F2` 이름 바꾸기(폴더)

텍스트 비교 보기 (IntelliJ 스타일): 한 줄 안의 변경은 **단어 단위**로 따로 강조되고(토큰 256개·표 16,384칸을 넘는 긴 줄은 앞뒤 공통부분을 뺀 구간 하나로 표시), 비교 옵션 중 대소문자·공백·앞뒤 공백·주석·식별자 이름 무시를 같은 규칙으로 따릅니다(대체 규칙은 단어 강조에 반영하지 않음), 툴바의 `단어 강조` 체크박스로 끌 수 있고(끄면 바뀐 줄 전체만 칠함), `스크롤 동기화` 체크박스로 두 창의 연동 스크롤을 끄고 켤 수 있습니다(다시 켜면 오른쪽 창이 왼쪽 위치로 맞춰짐). `공백 표시` 체크박스는 공백을 `·`, 탭을 `→` 로 회색 표시합니다(접기·통합 보기처럼 읽기 전용 표시이며, 탭은 한 글자로 표시되어 탭 정렬은 유지되지 않고, 켠 동안 찾기는 공백이 든 문자열을 찾지 못함), 현재 차이 블록은 거터에 위아래 윤곽선과 굵은 막대로 표시됩니다. `F7` / `Shift+F7` 은 설정과 상관없이 항상 다음 / 이전 차이로 이동합니다(기본 `F8` / `Shift+F8` 도 그대로).

**변경 없는 구간 접기** (툴바 체크박스): 변경 앞뒤 3줄만 남기고, 4줄 이상 이어지는 동일 구간은 `⋯ 변경 없는 줄 N개 접힘` 한 줄로 줄입니다. 접힌 보기는 읽기 전용 표시일 뿐이라 파일 내용은 그대로이고, 블록 복사·저장·바꾸기·수동 정렬 지정·엑셀 내보내기는 먼저 접기를 자동으로 풀고 실행합니다. `F7` / `F8` 이동과 거터·미니맵은 접힌 상태에서도 동작합니다. 접힌 줄의 거터 `⋯` 를 클릭하면 그 구간만 펼쳐지고(스크롤 위치와 현재 차이는 유지), 체크박스를 껐다 켜면 다시 모두 접힙니다. 접기 상태는 세션에 저장하지 않습니다.

**통합 보기** (툴바 체크박스): 창 하나에 모든 줄을 한 번씩 보여 줍니다. 변경 블록은 왼쪽 줄들 다음에 오른쪽 줄들이 이어지고, 수정된 줄 쌍에는 단어 단위 강조가 양쪽에 적용됩니다. 두 거터가 각각 왼쪽·오른쪽 줄 번호 열이 되며, 접기와 함께 쓸 수 있습니다. 접기와 마찬가지로 표시 전용이라 읽기 전용이고, 블록 복사·저장·바꾸기·정렬 지정·엑셀 내보내기는 먼저 통합 보기를 자동으로 풀고 실행합니다.

폴더 비교의 제외 목록과 내보내기:

- **제외 선택…** 버튼: 사용 중인 패턴, 마지막 스캔에서 찾은 폴더·확장자(항목 수 표시), 자주 쓰는 항목(`.git`, `node_modules`, `*.tmp` …)을 체크 목록으로 보여 줍니다. 직접 입력한 패턴도 추가할 수 있고, 확인하면 다시 비교합니다.
- 결과 목록에서 **오른쪽 클릭**: 선택한 항목을 `이름으로 제외` / `확장자로 제외` / `이 위치만 제외`.
- 패턴 규칙: `;` 로 구분, `*` `?` 사용 가능. 이름 패턴(`node_modules`, `*.log`)은 모든 하위 폴더에 적용되고, `\` 로 시작하는 패턴(`\src\build`)은 비교 루트 기준 그 위치의 항목만 제외합니다. 전체 길이는 255자까지입니다.
- **보고서 · 내보내기** 버튼: Excel(.xlsx) / Word(.docx) / HTML 중에서 고릅니다. 상태 필터(같음·다름·왼쪽만·오른쪽만)에서 켜 둔 항목만 내보냅니다. xlsx는 머리글 고정·자동 필터·크기 숫자 서식, docx는 가로 A4 표입니다. 파일은 압축하지 않은 ZIP(OOXML)로 기록합니다.

설정 / 정책 / 외부 도구 (CU-01·CU-02·EX-01):

- 설정은 `%LOCALAPPDATA%\BeCompareAsm\settings.ini` 에 저장됩니다. 글꼴은 다시 시작해야 적용되고, 색·단축키는 즉시 적용됩니다.
- 외부 도구: `[External]` 섹션에 `.확장자=명령줄` (`%1` = 왼쪽 파일, `%2` = 오른쪽 파일). 폴더 비교에서 해당 확장자 파일을 더블클릭/Enter 하면 내부 비교 대신 실행됩니다.

## 검증 방법

- `python tools/test_regressions.py`: 격리된 입력·설정 경로에서 전체 재빌드와 저장 오류 주입, 변경 상태·종료·스레드 취소, 화면 동작, 명령줄 비교·보고서·내보내기·동기화 회귀 검사 381개를 실행합니다.
- 화면 동작 검사(`tools/test_ui.c`, 264개): 앱 전체를 테스트 프로세스 안에서 창을 숨긴 채 실행하고, 실제 RichEdit 컨트롤에서 글자별 배경색을 읽습니다. 텍스트 비교의 행 색(수정·삭제·삽입·빈 쪽)과 단어 단위 강조, 긴 줄의 접두·접미 강조를 밝은 테마와 어두운 테마에서 확인하고, F7 / Shift+F7과 이전·다음 차이 버튼의 이동 위치를 확인합니다. 구문 강조를 켜고 껐을 때의 글자색과 수정 표시, 색칠이 실행 취소 단계로 남지 않는지, 병합 세션 세 창의 색상도 확인합니다. 폴더 병합은 출력 폴더로 실제 실행해 요약 집계(병합됨·미해결 충돌·복사 실패)와 결과 파일을 확인합니다. `BC_UITEST_SHOW=1`을 주면 창을 보면서 실행합니다. 거터·미니맵처럼 직접 그리는 부분과 텍스트 비교·병합 외의 세션 화면은 이 검사에 없습니다.
- XLSX 시트 선택: 경로 뒤에 `#시트이름`(대소문자 무시) 또는 `#번호`(탭 순서, 1부터)를 붙입니다. 붙이지 않으면 이전처럼 첫 워크시트 파트(`sheet1.xml`)를 읽습니다. 없는 시트를 지정하면 읽기 실패로 처리합니다. `&`처럼 XML에서 바꿔 적는 문자가 든 시트 이름은 이름으로 찾지 못하므로 번호를 쓰세요.
- 임시 파일: ZIP·FTP에서 꺼낸 파일과 클립보드·패치 비교용 파일은 `%TEMP%\BeCompareAsm\<프로세스 ID>_...` 폴더에 두고, 앱이 끝날 때 자기 폴더와 이미 끝난 프로세스의 폴더를 지웁니다. 실행 중인 다른 프로세스의 폴더와 이 형식이 아닌 이름은 건드리지 않습니다. 강제 종료된 경우에는 다음에 실행한 앱이 끝날 때 지워집니다.
- 접근할 수 없는 폴더가 있을 때 동기화를 막는 검사는 폴더에 거부 권한을 걸어 확인하는데, 권한을 걸어도 폴더가 열리는 계정에서는 건너뜁니다(`SKIP` 출력).
- 화면 동작 검사는 그 밖에 탭 줄 버튼의 위치와 동작(현재 탭 닫기, 홈 탭은 닫지 않음, 종료), 모든 버튼·체크 상자·입력 칸·콤보 상자에 풍선 도움말이 있는지, 화면 밖으로 걸친 창에서 연 폴더 찾아보기 창과 확인 버튼이 작업 영역 안에 있는지, 홈의 파일 찾기(폴더 트리 검색, 다섯 열의 내용, 열마다의 정렬과 방향 전환, 드라이브·종류·클라우드·확장자·폴더 필터와 그 조합, 더블클릭과 메뉴의 다섯 동작, 드라이브 전체를 파일 테이블에서 읽어 방금 만든 파일 찾기)를 확인합니다. 열기 동작은 테스트에서 실제 프로그램을 띄우거나 클립보드를 바꾸지 않고 호출 내용만 확인합니다. 드라이브 전체 검사는 볼륨을 열 권한이 없으면 건너뜁니다(`SKIP` 출력).

## 알려진 한계

- 텍스트 비교는 LCS 표(최대 3천만 칸)를 쓰므로 서로 크게 다른 대용량 파일은 Myers 알고리즘으로 넘어갑니다.

- 헥스 비교는 파일 전체를 메모리에 올립니다.
- 파일 찾기:
  - 첫 검색 때 고정 드라이브(이동식·네트워크 드라이브 제외)의 이름·폴더·수정 시각·크기를 메모리에 색인합니다. NTFS 드라이브는 세 가지 방식을 차례로 시도합니다. ① 파일 테이블(MFT)을 볼륨에서 직접 읽어 해석(관리자 권한 필요, 드라이브당 몇 초, 날짜·크기 포함) ② 파일 테이블 열거(관리자 권한, 이름만 있어 날짜·크기 열이 비고 날짜·크기 정렬이 의미 없음) ③ 폴더 순회(권한 불필요, 훨씬 오래 걸림, 날짜·크기 포함). 색인 중에도 그때까지 읽은 범위에서 검색됩니다. ①은 파일 테이블이 매우 심하게 조각나 있으면 쓰지 못하고 ②로 넘어갑니다.
  - 색인은 만든 시점의 모습입니다. 그 뒤에 생기거나 지워진 파일은 앱을 다시 실행해야 반영됩니다.
  - 이름에 입력한 글자가 들어 있는지를 봅니다(대소문자 무시). 와일드카드·정규식·내용 검색은 없습니다. 결과는 400만 개까지 보관해 정렬합니다.
  - 결과 목록은 탐색기의 자세히 보기처럼 이름·수정한 날짜·유형·크기·폴더 열로 보여 줍니다. 처음에는 최신 순이고, 열 머리글을 누르면 그 열로 정렬하며 한 번 더 누르면 방향이 바뀝니다(머리글에 ▲/▼ 표시). 날짜·크기는 큰 것부터, 이름·유형·폴더는 가나다순부터 시작합니다. 폴더 열 정렬은 결과가 5만 개 이하일 때만 하고, 넘으면 이름순으로 보여 줍니다. 큰 아이콘·목록 같은 다른 보기 방식은 없습니다.
  - 드라이브 필터: 색인한 드라이브 중 하나만 고릅니다.
  - 클라우드 필터(포함 / 제외 / 클라우드만): 클라우드 저장소 폴더 안에 있는지로 가립니다. 폴더는 환경 변수 `OneDrive`·`OneDriveConsumer`·`OneDriveCommercial`과 Windows에 등록된 동기화 루트(레지스트리 `SyncRootManager`: OneDrive, Dropbox, iCloud Drive 등)에서 찾습니다. 파일이 온라인 전용인지는 구분하지 않습니다. 가상 드라이브로 붙는 Google Drive(스트리밍 모드)는 드라이브 필터로 가리세요. 색인이 끝난 뒤에 폴더를 찾으므로 색인 중에는 이 필터가 적용되지 않습니다.
  - 그 밖의 필터: 종류(전체 / 파일만 / 폴더만 / 문서·이미지·음악·동영상·압축·소스 코드·실행 파일 묶음), 확장자(`pdf;docx`처럼 여러 개, 적으면 종류의 확장자 묶음 대신 쓰임), 폴더(들어 있는 폴더 경로에 그 글자가 있는 것만). 이름을 비워도 필터만으로 찾을 수 있습니다. 크기·날짜 범위 필터는 없습니다.
  - 찾은 항목은 더블클릭하면 Windows에 연결된 프로그램으로 엽니다(폴더는 탐색기). 연결된 프로그램이 없으면 프로그램 선택 창이 뜹니다. 우클릭 메뉴의 "BeCompare에서 열기"는 그 파일 형식에 맞는 비교 세션을 새로 만들어 왼쪽에 넣습니다.
  - 항목 100만 개당 메모리를 약 80MB 씁니다(항목 32바이트 + 이름 길이로 계산한 값, 측정하지 않음).
- 다크 모드에서 탭 컨트롤 머리글은 시스템 테마(밝은색)를 따릅니다.
- 아이콘 버튼(Segoe MDL2 글리프 + 툴팁)은 폴더 비교·텍스트 비교·헥스·이미지·텍스트 병합·폴더 병합 보기의 도구 모음에 적용했습니다(표·버전·레지스트리·미디어·편집 보기는 동작 버튼이 적거나 없어 텍스트 버튼 그대로). 도구 모음은 창이 좁아지면 다음 줄로 넘어갑니다(폴더·텍스트·헥스·표·병합·이미지·폴더 병합).
- SFTP/FTPS, 클라우드, Subversion, MTP, MSSCCI, 자동 업데이트, macOS/Linux 포팅은 이 환경에서 구현·검증할 수 없어 제외했습니다.
